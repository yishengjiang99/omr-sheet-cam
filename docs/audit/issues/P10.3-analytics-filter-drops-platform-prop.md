title: [P10.3] Analytics key filter regex matches "lat" in "platform" and silently drops it from event props

**Step ID:** P10.3 (also F1.2)
**Flow:** P10 Telemetry, privacy & compliance of the purchase funnel
**Static verdict from audit:** GAP (confirmed by code trace)
**Build / env:** traced at HEAD `736d0f6` (main) · iOS 17+ · static code trace, not yet reproduced on device/Simulator · StoreKit env: Xcode config (needs attach, see P11.3) / Sandbox · Apple ID type: sandbox tester

### Expected
PII filter drops only PII-looking keys (email, phone, gps, lat/lng...); props `product`, `plan`, `reason`, `platform`, `app_version` survive.

### Actual
`Analytics.track` filters prop keys with an unanchored regex `email|phone|image|photo|base64|gps|lat|lng|token|password`. `"lat"` matches `"platform"` (and any key containing `lat`, e.g. `latency`, `translate`, `relation`, `template`), so `app_open{platform:"ios"}` loses `platform` from props. (`platform` is also sent at top level, line 64, so impact is limited to props.) Also `image`/`photo`/`token` substring-match future legit keys.

### Location
- `Sources/App/Services/Analytics.swift:53` (regex filter)
- `Sources/App/Services/Analytics.swift:44-47` (app_open props incl. platform)
- `Sources/App/Services/Analytics.swift:64` (top-level platform)
Root cause (1-2 lines): Substring regex on keys; no word-boundary/exact-key allow/deny list.

### Repro
1. Unit: `Analytics.shared.track("x", props: ["platform":"ios"])` and capture the payload (or read `app_open` POST body).
2. Observed: `props` is `{app_version: ...}` only.

Repro rate: always
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P3 — analytics gap only; no PII or user impact.

### Suggested fix
Use an exact-key deny set (`["email","phone","gps","lat","lng","token","password","image","photo","base64"]`) or anchored regex `^(email|phone|...)$`; make `track` testable by factoring `clean(props:)`.
