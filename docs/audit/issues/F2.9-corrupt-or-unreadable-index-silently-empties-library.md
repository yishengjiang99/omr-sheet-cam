**Step ID:** F2.9 (also F11.4)
**Flow:** F2 Library home (browse / search / rename / delete)
**Static verdict from audit:** GAP (confirmed by code trace; the existing test enshrines the behavior)
**Build / env:** traced at HEAD `736d0f6` (main) · iOS 17+ · static code trace, not yet reproduced on device/Simulator · StoreKit env: Xcode config (needs attach, see P11.3) / Sandbox · Apple ID type: sandbox tester

### Expected
A corrupt/unreadable index is surfaced to the user and recoverable (backup or rebuild from `*.mid`/`*.layout.json` files); entries are never silently destroyed.

### Actual
`loadIndex()` returns `[]` when the file cannot be read or decoded (only a warn log). The `.mid` files remain on disk as orphans with no index entry, and the first `addScan`/`rename`/`delete` calls `saveIndex()`, atomically overwriting index.json with only the new entries - the old index is lost permanently. A future schema change to `PlaylistEntry` (new required field) would trigger the same wipe on update. Entries whose `.mid` is missing are also dropped silently (and then removed from the index on next save).

### Location
- `Sources/App/Player/PlaylistStore.swift:98-113` (loadIndex -> [] on failure)
- `Sources/App/Player/PlaylistStore.swift:115-121` (saveIndex overwrites)
- `Tests/PlaylistStoreTests.swift:105-121` ("A corrupt index is replaced on the next save")
Root cause (1-2 lines): No backup/recovery and no distinction between "no index yet" and "index unreadable".

### Repro
1. Add 2 scans. Overwrite `Application Support/playlist/index.json` with `not json` (Simulator).
2. Relaunch: Library "Your scans" empty. Scan one more: index.json now has 1 entry; the 2 old `.mid` files are orphaned.

Repro rate: always when the index is unreadable (rare trigger)
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P2 — silent data loss but low trigger probability (atomic writes), so P2.

### Suggested fix
On decode failure rename the bad file to `index.json.corrupt-<ts>`, rebuild entries by scanning `*.mid` (+ capture timestamps), and show a banner; use tolerant decoding (`decodeIfPresent`) with versioned schema.
