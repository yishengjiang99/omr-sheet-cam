### Summary
The moment a scan succeeds is the highest-intent point: the user has just seen value. Show a small inline card (not a modal) below the summary, only for free users, capped by the shared policy.

### What the code does today
- Success path: `ResultScreen.recognize` sets `outcome = result`, records telemetry and calls `saveToPlaylist(d)` (`Sources/App/Capture/ResultScreen.swift:252-254,263-270`).
- Result UI: recognized list starts with title field + summary Section (`ResultScreen.swift:93-107`) followed by `OMRCompareView` (:108-111); pinned Play bar at :81-85.
- No Pro/quota information reaches `ResultScreen` today (it has no access to `ScanQuota`/`StoreKitManager`).

### Proposed hook points (file:line at HEAD)
- `Sources/App/Capture/ResultScreen.swift:102-107` - add `if showUpgradeCard { UpgradeCard(remaining:, onLearnMore:, onDismiss:) }` inside the summary Section; decide `showUpgradeCard` once in `recognize` right after `saveToPlaylist(d)` (:269) via `UpgradePromptPolicy` (reason `.postScan`), only when `scansRemaining <= 2` or on the 3rd lifetime successful scan.
- `Sources/App/Capture/ResultScreen.swift:11` - inject `@EnvironmentObject StoreKitManager` (already provided at `RootFlowView.swift:53`) and `ScanQuota.shared` for remaining count.
- Tap "See Pro" -> `ScanQuota.shared.requestPaywall(.postScan)` (user-initiated, so the sheet opens at `RootFlowView.swift:50-52`). Dismiss "x" -> record in policy.

### App Review guardrails (must all hold)
- Never blocks core use: scanning within quota, playback, Library, share and Settings stay fully usable; the prompt is dismissible and never re-appears in the same session after dismissal.
- Easy dismiss: visible Close/"Not now" control with no delay or countdown, swipe-down works, no dark patterns (no pre-checked purchase, no fake urgency/scarcity, no guilt copy).
- Frequency cap: shared policy (see the [P2.1] policy issue) - max 1 unsolicited prompt per calendar day and 3 per 7 days, never in the first session, never within 60 s of a previous prompt; the quota-hit paywall is user-initiated by the scan attempt and is exempt.
- Respect Pro/restored state: no prompt when `omr.isPro` is true (after the P7.4 fix, the live entitlement) or while a purchase/restore/pending approval is in progress.
- Accurate disclosure (Guideline 3.1.2): any screen that shows a price also shows billing period, renewal text, Terms and Privacy links and a Restore control, exactly as the existing PaywallView does.
- Telemetry (if added) uses the existing anonymous funnel only and the new event names are added to the privacy page and PrivacyInfo text before release.
