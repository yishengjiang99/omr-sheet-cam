**Flow:** F4 Photos import & "Try sample picture"
**Static verdict from audit:** GAP (confirmed by code trace)
**Build / env:** traced at HEAD `736d0f6` (main) · iOS 17+ · static code trace, not yet reproduced on device/Simulator · StoreKit env: Xcode config (needs attach, see P11.3) / Sandbox · Apple ID type: sandbox tester

### Expected
Both entry points show the same visible error when the sample cannot load; the sample does not silently consume a real scan (product decision).

### Actual
`RootFlowView.trySample` (Library) catches the error and only writes to `DiagnosticsLog`; nothing is shown to the user, whereas `CameraScreen.trySample` sets `error = "Could not load the sample picture"`. On success the sample goes through `handlePhoto` and consumes 1 of the 5 daily scans (design flag in flows.md P1.3).

### Location
- `Sources/App/RootFlowView.swift:66-76` (catch only logs at :72-73)
- `Sources/App/Capture/CameraScreen.swift:228-242` (shows error)
Root cause (1-2 lines): Two separate implementations of the sample action with different error handling.

### Repro
1. Debug build without `ode-to-joy.jpg` bundled; tap Try sample picture on empty Library: nothing happens.

Repro rate: always when the resource is missing (unlikely in release)
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P3 — cosmetic/edge.

### Suggested fix
Add an alert/inline error in `RootFlowView` (or reuse LibraryScreen `importError`); consider not charging quota for `source == .sample`.
