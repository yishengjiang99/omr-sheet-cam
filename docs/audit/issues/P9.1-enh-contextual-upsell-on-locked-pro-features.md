**Type:** Product enhancement (not a defect). Traced at HEAD `736d0f6`.

### Summary
Today Pro unlocks exactly one thing (unlimited scans); all player features are free, which is also what the paywall copy, ASC description and review notes promise. A contextual "locked feature" upsell only makes sense if the product first moves some feature behind Pro. This issue documents the hook points and the required copy/review changes; it must NOT ship without that product decision.

### What the code does today
- `rg isPro` shows only ScanQuota/StoreKitManager read it (`Sources/App/Services/ScanQuota.swift:23,41`); no view gates anything.
- Paywall copy: "Free: ... Pro unlocks unlimited scans" and the comparison lists identical features (`Sources/App/Features/Paywall/PaywallView.swift:16,103-120`); review notes say "everything else is the same for free users" (`docs/asc/metadata/review_information/notes.txt`).
- Candidate controls (all free today): instrument chip `Sources/App/Player/PlayerView.swift:335-341`, key transpose `:308-316` (`PlaybackController.setTranspose` `Sources/App/Player/PlaybackController.swift:90`), tempo `:324-330`, hands `:248-264`, A-B loop (`PlaybackController.markLoopPoint` :160).

### Proposed hook points (file:line at HEAD)
- Gate at the action, not the screen: wrap e.g. `PlaybackController.setTranspose` (:90) / loop marking (:160) with `guard entitlement.allows(.transpose) else { onLocked(.transpose); return }`, showing a lock glyph on the chip (`PlayerView.swift:308-316`) and presenting the paywall with `reason: .feature("transpose")` via `ScanQuota.requestPaywall` (user tapped it, so exempt from the cap).
- Never gate already-saved content: playback, share and Library of existing scans stay free (P9.5 must keep passing).
- Update `PaywallView.comparison` (:103-122), ASC description/review notes and the privacy page ("Pro features") to list the real differences.

### App Review guardrails (must all hold)
- Never blocks core use: scanning within quota, playback, Library, share and Settings stay fully usable; the prompt is dismissible and never re-appears in the same session after dismissal.
- Easy dismiss: visible Close/"Not now" control with no delay or countdown, swipe-down works, no dark patterns (no pre-checked purchase, no fake urgency/scarcity, no guilt copy).
- Frequency cap: shared policy (see the [P2.1] policy issue) - max 1 unsolicited prompt per calendar day and 3 per 7 days, never in the first session, never within 60 s of a previous prompt; the quota-hit paywall is user-initiated by the scan attempt and is exempt.
- Respect Pro/restored state: no prompt when `omr.isPro` is true (after the P7.4 fix, the live entitlement) or while a purchase/restore/pending approval is in progress.
- Accurate disclosure (Guideline 3.1.2): any screen that shows a price also shows billing period, renewal text, Terms and Privacy links and a Restore control, exactly as the existing PaywallView does.
- Telemetry (if added) uses the existing anonymous funnel only and the new event names are added to the privacy page and PrivacyInfo text before release.

### Acceptance checks
- [ ] Manual: free user taps locked Transpose -> paywall titled for that feature, Close returns to the player with playback uninterrupted; Pro user is never prompted.
- [ ] Automated: `Entitlement.allows` unit tests (free/Pro/expired), XCUITest locked chip -> paywall -> Close keeps playing.
- [ ] Regression: P9.5 (content kept after lapse), P9.6, F10.8.

### Priority
P3 (enhancement) — Blocked on a product decision (which features, if any, become Pro). Review risk is highest here: guideline 3.1.1/5.6 - do not remove features users already had without notice; consider only gating new features.
