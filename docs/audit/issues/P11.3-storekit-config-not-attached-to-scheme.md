### Expected
`OMRSheetCam.storekit` is referenced by the project and selected in Scheme > Run > Options > StoreKit Configuration so Debug runs/simulator load both products and Xcode StoreKit testing (expire, refund, Ask to Buy) works.

### Actual
`OMRSheetCam.storekit` exists at the repo root but is not referenced in `project.pbxproj` (no file reference) and the shared scheme `LaunchAction` has no `StoreKitConfigurationFileReference` (both greps return 0). Only `PaywallScreenshotTests` loads it programmatically via `SKTestSession(contentsOf:)`. `docs/omr-iap-xcode-prompt.md` Step 3 was never committed. In a Debug simulator run `Product.products(for:)` returns empty/throws, so the paywall shows the load-failure state.

### Location
- `OMRSheetCam.xcodeproj/xcshareddata/xcschemes/OMRSheetCam.xcscheme:43-63` (LaunchAction without StoreKitConfigurationFileReference)
- `OMRSheetCam.xcodeproj/project.pbxproj` (no reference to OMRSheetCam.storekit)
- `Tests/PaywallScreenshotTests.swift:26-27` (only consumer, opt-in)
Root cause (1-2 lines): Config file added to repo but never wired into project/scheme.

### Repro
1. `grep -c storekit OMRSheetCam.xcodeproj/project.pbxproj` -> only StoreKitManager.swift matches (no .storekit).
2. Open scheme > Run > Options: StoreKit Configuration = None.
3. Run in simulator, trigger paywall: no plans load.

Repro rate: always
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P2 — blocks local verification of the entire P-flow suite (S-cases) and screenshots; no end-user impact.

### Suggested fix
In Xcode add `OMRSheetCam.storekit` to the project (file reference, no target membership) and set it on the shared scheme: `<StoreKitConfigurationFileReference identifier = "../../OMRSheetCam.storekit"/>` under `LaunchAction` (plus TestAction if StoreKit tests are added). Commit the scheme change.
