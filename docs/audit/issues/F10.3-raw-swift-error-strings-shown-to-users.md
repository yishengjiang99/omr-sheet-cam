### Expected
User-facing errors are short plain-language messages; raw details live in the diagnostics log/Details disclosure.

### Actual
Several UI strings interpolate `\(error)`: player "Can't play this: \(error)", Result "Save failed: \(e)" / "Could not save to playlist: \(error)", Library "Delete failed: \(error)" / "Rename failed: \(error)", Sample "Sample unavailable: \(error)". These expose enum case names and NSError dumps.

### Location
- `Sources/App/Player/PlaybackController.swift:288`
- `Sources/App/Capture/ResultScreen.swift:237,287,369`
- `Sources/App/Player/LibraryScreen.swift:235,300`
Root cause (1-2 lines): No user-facing error mapping layer.

### Repro
1. Delete a `.mid` file by hand, open the scan: status shows "Can't play this: notFound(...)".

Repro rate: always when triggered
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P3 — polish.

### Suggested fix
Introduce `UserFacingError.message(for:)` mapping known errors; keep raw text in log/Details.
