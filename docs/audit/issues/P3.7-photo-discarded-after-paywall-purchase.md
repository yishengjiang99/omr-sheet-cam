**Static verdict from audit:** GAP (confirmed by code trace)
**Build / env:** traced at HEAD `736d0f6` (main) · iOS 17+ · static code trace, not yet reproduced on device/Simulator · StoreKit env: Xcode config (needs attach, see P11.3) / Sandbox · Apple ID type: sandbox tester

### Expected
After a successful purchase the scan that triggered the paywall continues with the same photo (Reading starts), or at minimum the photo is kept for one tap.

### Actual
`handlePhoto(_ photo:)` calls `checkAndConsume()`; when it returns false the `CapturedPhoto` is simply dropped (no stored pending photo). A camera shot is not stored anywhere else (captures are only saved later in `ResultScreen.saveCapture`), so it is lost; the Photos picker has already closed. After purchase the paywall dismisses and the user is back on Camera/Library and must shoot/pick again.

### Location
- `Sources/App/RootFlowView.swift:57-63` (photo dropped when gate returns false)
- `Sources/App/Features/Paywall/PaywallView.swift:80-85` (dismiss() only)
- `Sources/App/Services/ScanQuota.swift:30-35` (reject path)
Root cause (1-2 lines): No pending-photo state and no post-purchase continuation hook.

### Repro
1. Set `omr.freeScansUsed` = 5 (today).
2. Camera: take a photo of a page -> paywall appears.
3. Subscribe (sandbox/StoreKit) -> sheet closes. Observed: no Reading screen, photo gone.

Repro rate: always
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P1 — data loss of the user's capture at the exact moment of conversion (rubric: data loss) and a bad first-paid experience; scoped to one photo, so P1 not P0.

### Suggested fix
Keep `@State pendingPhoto: CapturedPhoto?` in `RootFlowView`; set it when the gate rejects; on paywall dismiss with `storeKit.isPro == true` (observe `storeKit.purchasedProductIDs`/isPro) call `handlePhoto(pendingPhoto)` again; clear on Close. Alternative: persist the capture first and offer "Scan now".
