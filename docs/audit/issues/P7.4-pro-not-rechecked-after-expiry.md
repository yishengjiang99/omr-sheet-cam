**Step ID:** P7.4 (also P9.3, P7.1, P7.12)
**Flow:** P7 Entitlement checks, renewal, expiry, refund, offline
**Static verdict from audit:** GAP (confirmed by code trace; confirm runtime with StoreKit test S12)
**Build / env:** traced at HEAD `736d0f6` (main) · iOS 17+ · static code trace, not yet reproduced on device/Simulator · StoreKit env: Xcode config (needs attach, see P11.3) / Sandbox · Apple ID type: sandbox tester

### Expected
After the subscription `expirationDate`, the next scan attempt shows the paywall without relaunching the app. Pro is derived from current entitlements, not a once-per-launch cached flag.

### Actual
`omr.isPro` is a plain UserDefaults bool. It is rewritten only (a) in `StoreKitManager.init` via `refreshEntitlements()`, (b) after a successful `restore()`, (c) by `grantPro`/`revokePro` when `Transaction.updates` yields a transaction. Plain expiry does not produce a `Transaction.updates` event, and there is no `scenePhase`/foreground hook. `ScanQuota.checkAndConsume()` reads only the cached flag, so a lapsed user keeps unlimited scans for the whole process lifetime (a backgrounded iOS app can live for days). Also at cold start the first scans race the async refresh and use the stale flag (P7.1 note).

### Location
- `Sources/App/Services/StoreKitManager.swift:23-28` (refresh only in init)
- `Sources/App/Services/StoreKitManager.swift:34-36` (isPro = cached UserDefaults)
- `Sources/App/Services/StoreKitManager.swift:105-122` (listener: no expiry handling)
- `Sources/App/Services/StoreKitManager.swift:124-141` (refreshEntitlements, never re-invoked)
- `Sources/App/Services/ScanQuota.swift:23` (gate reads cached flag)
- `Sources/App/RootFlowView.swift:57-63` (no refresh before gate)
Root cause (1-2 lines): Entitlement is computed once per process and cached in UserDefaults; nothing re-evaluates it on foreground or before the quota gate.

### Repro
1. Xcode StoreKit config attached (see P11.3) or Sandbox; fresh install.
2. Buy Monthly. Debug > StoreKit > Manage Transactions > Expire Subscription (or let sandbox monthly lapse, ~5 min).
3. Do NOT kill the app. Background/foreground it; use all 5 free scans plus a 6th the same day.
4. Observed: 6th and later scans proceed; paywall never shown. Kill + relaunch -> paywall shown.

Repro rate: always (static: no code path re-evaluates); confirm timing of Transaction.updates with S12
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P1 — revenue leak - lapsed users keep unlimited scans for as long as the process lives.

### Suggested fix
Call `await storeKit.refreshEntitlements()` on `scenePhase == .active` and at the start of the scan gate (make the gate async or refresh in `handlePhoto` before `checkAndConsume`). Derive Pro from `Transaction.currentEntitlements` (honours `expirationDate`) instead of a persisted flag; keep the flag only as an offline cache. Inject ONE `StoreKitManager` into `ScanQuota` (see P1.12 issue).
