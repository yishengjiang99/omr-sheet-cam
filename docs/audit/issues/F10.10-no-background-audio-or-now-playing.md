**Build / env:** traced at HEAD `736d0f6` (main) · iOS 17+ · static code trace, not yet reproduced on device/Simulator · StoreKit env: Xcode config (needs attach, see P11.3) / Sandbox · Apple ID type: sandbox tester

### Expected
A music player keeps playing with the screen locked or the app backgrounded and exposes lock-screen controls (play/pause, title) via `MPNowPlayingInfoCenter`/`MPRemoteCommandCenter`.

### Actual
The audio session is `.playback` and is activated, but the app declares no `UIBackgroundModes` (`INFOPLIST_KEY_UIBackgroundModes` absent in `project.pbxproj`, no Info.plist file exists), so iOS suspends the app and audio stops when the screen locks/auto-locks or the user switches apps. `rg MPNowPlaying|MPRemoteCommand` returns nothing; interruption/route-change handling exists but there is no lock-screen UI.

### Location
- `OMRSheetCam.xcodeproj/project.pbxproj:678-687` (generated Info.plist keys; no UIBackgroundModes)
- `Packages/SF2Player/Sources/SF2Player/SF2MIDIPlayer.swift:236-241` (AVAudioSession .playback)
- `Packages/SF2Player/Sources/SF2Player/SF2MIDIPlayer.swift:433-462` (interruption/route handling only)
- `Sources/App/Player/PlaybackController.swift` (no MPNowPlayingInfoCenter / remote command wiring)
Root cause (1-2 lines): Background audio capability and Now Playing integration were never added.

### Repro
1. Play a scan/sample in Player on a device.
2. Lock the device (or Home). Observed: audio stops (expected to continue).

Repro rate: needs device only (static evidence: capability absent)
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P2 — core-flow gap for a music app (leave phone on the piano, screen auto-locks); P2 because pieces are short and playback can resume.

### Suggested fix
Add `INFOPLIST_KEY_UIBackgroundModes = audio` (via build setting `INFOPLIST_KEY_UIBackgroundModes`/Info.plist), wire `MPNowPlayingInfoCenter` (title, duration, elapsed) and `MPRemoteCommandCenter` (play/pause/next/prev/seek) in `PlaybackController`. Note ASC review: background audio needs a justification string.
