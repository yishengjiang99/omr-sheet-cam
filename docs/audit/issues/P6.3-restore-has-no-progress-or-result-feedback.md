**Step ID:** P6.3 (also P6.2, P6.4, P6.5, P6.7)
**Flow:** P6 Restore purchases
**Static verdict from audit:** GAP (confirmed by code trace)
**Build / env:** traced at HEAD `736d0f6` (main) · iOS 17+ · static code trace, not yet reproduced on device/Simulator · StoreKit env: Xcode config (needs attach, see P11.3) / Sandbox · Apple ID type: sandbox tester

### Expected
Tap Restore -> visible progress and disabled button; success -> Pro unlocked + user told + paywall closes; nothing found -> explicit message; user cancelling the Apple ID prompt -> silent; network failure -> readable retryable message.

### Actual
`restore()` sets `isLoading=true` but nothing in `PaywallView` renders `isLoading` for restore (it is only used in the "Could not load products" condition) and the button is never disabled, so double-taps start multiple `AppStore.sync()` calls. On success `refreshEntitlements()` silently flips the flag; the sheet stays open and no message is shown. With no entitlement the flag is set false and nothing is said. Any thrown error, including the user dismissing the Apple ID sign-in (`StoreKitError.userCancelled`), is shown as red "Restore failed: <raw localizedDescription>". No `restore_*` telemetry.

### Location
- `Sources/App/Services/StoreKitManager.swift:93-103` (restore: no result state)
- `Sources/App/Services/StoreKitManager.swift:124-141` (refreshEntitlements returns Void)
- `Sources/App/Features/Paywall/PaywallView.swift:43-47` (button never disabled / no spinner)
- `Sources/App/Features/Paywall/PaywallView.swift:27,35-41` (isLoading not shown for restore; error box)
Root cause (1-2 lines): `restore()` returns Void and exposes no state machine (restoring / restored / nothingToRestore / failed / cancelled).

### Repro
1. Paywall open, StoreKit config with an active sub on the test account.
2. Tap Restore. Observed: no spinner, button still enabled, Pro granted silently, sheet stays open.
3. Repeat with no subscription: nothing visible. Cancel the Apple ID prompt: red "Restore failed".

Repro rate: always
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P2 — misleading/no feedback with workaround (relaunch / look at scan limit); mostly UX but hits review-critical flow.

### Suggested fix
Make `restore()` return an enum result (`.restored/.nothing/.cancelled/.failed(String)`); add `@Published isRestoring`; PaywallView shows spinner + disables Restore, dismisses (or shows "Pro restored") on success, shows "No active subscription found for this Apple ID" on `.nothing`, ignores `StoreKitError.userCancelled`; emit `restore_start/success/fail` events (update PrivacyInfo/policy text accordingly).

### Acceptance test

- [ ] Automated: SKTestSession: active -> `restore()` == .restored and `isPro`; cleared -> == .nothing; XCTest with injected failing sync -> == .failed, userCancelled -> == .cancelled.
