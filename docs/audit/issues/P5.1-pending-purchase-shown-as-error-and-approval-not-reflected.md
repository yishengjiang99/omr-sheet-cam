**Flow:** P5 Pending / Ask to Buy / SCA
**Static verdict from audit:** GAP (confirmed by code trace)
**Build / env:** traced at HEAD `736d0f6` (main) · iOS 17+ · static code trace, not yet reproduced on device/Simulator · StoreKit env: Xcode config (needs attach, see P11.3) / Sandbox · Apple ID type: sandbox tester

### Expected
`.pending` shows a neutral "Waiting for approval - we'll unlock Pro when it's approved" message (not error styling, not `purchase_fail`). When the approval arrives via `Transaction.updates` the paywall reflects it (auto-close / "Pro unlocked"). Declined clears the message.

### Actual
`.pending` sets `purchaseError = "Purchase is pending approval."`, which `PaywallView` renders in the red error box, and fires `purchase_fail{reason:pending}`. When approval later arrives, the listener calls `grantPro` (flag becomes true) but nothing observes it: `isPro` is not `@Published`, the paywall stays open with the stale pending text. Declined/expired requests never clear the message.

### Location
- `Sources/App/Services/StoreKitManager.swift:79-82` (pending -> purchaseError + purchase_fail)
- `Sources/App/Services/StoreKitManager.swift:105-118` (listener grants silently)
- `Sources/App/Services/StoreKitManager.swift:34-36` (isPro not @Published)
- `Sources/App/Features/Paywall/PaywallView.swift:35-41` (red box for any purchaseError)
Root cause (1-2 lines): Single `purchaseError` string for all outcomes; no published Pro state for the UI to observe.

### Repro
1. Xcode StoreKit: Editor > Enable Ask to Buy. Hit paywall; Subscribe.
2. Observed: red "Purchase is pending approval." Approve in Transaction Manager: flag flips, sheet unchanged.

Repro rate: always
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P2 — misleading messaging on a rare path, with workaround (close paywall, scan).

### Suggested fix
Add `@Published var status: PurchaseStatus` (`.idle/.pending/.error(msg)`) and `@Published private(set) var isPro`; render pending in neutral style; PaywallView `.onChange(of: storeKit.isPro) { if $0 { dismiss() } }`; log `purchase_pending` instead of `purchase_fail`.

- [ ] Automated: SKTestSession with `askToBuyEnabled = true`: `purchase()` returns false and `status == .pending`; `session.approveAskToBuyTransaction` -> `isPro` becomes true.
