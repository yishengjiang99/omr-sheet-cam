### Expected
Plain-language messages by error type (payment declined, offline, not available in storefront, verification failed); unverified result leaves the transaction unfinished and tells the user "We couldn't verify this purchase - try Restore".

### Actual
All errors fall into one `catch` that sets `purchaseError = error.localizedDescription` and event `purchase_fail{reason:error}`. `.success(.unverified)` goes through `checkVerified` which throws the raw `VerificationError`, so the user sees a cryptic Apple/Swift string, the telemetry reason is the same as every other error, and `.unknown`/`@unknown default` return false silently with no message.

### Location
- `Sources/App/Services/StoreKitManager.swift:68-90` (single catch; unknown default silent at :83-84)
- `Sources/App/Services/StoreKitManager.swift:153-160` (checkVerified throws raw error)
Root cause (1-2 lines): No error classification layer.

### Repro
1. StoreKit config > Editor > Default StoreKit Errors > Verification failed (or "Fail Transactions"); Subscribe.
2. Observed: raw system string in the red box.

Repro rate: always when triggered
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P3 — copy/UX on failure paths.

### Suggested fix
Map `StoreKitError`/`Product.PurchaseError`/`VerificationResult.VerificationError` to short user strings and distinct `reason` values; handle `@unknown default` with a generic message.
