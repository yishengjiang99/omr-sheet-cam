**Step ID:** F11.2 (also F2.5)
**Flow:** F11 Library playback, mini-player, playlist behavior
**Static verdict from audit:** GAP (confirmed by code trace; behavior on device [RUNTIME])
**Build / env:** traced at HEAD `736d0f6` (main) · iOS 17+ · static code trace, not yet reproduced on device/Simulator · StoreKit env: Xcode config (needs attach, see P11.3) / Sandbox · Apple ID type: sandbox tester

### Expected
Deleting the playing scan stops playback / clears the mini-player (or is blocked).

### Actual
`LibraryScreen.delete` only calls `store.delete`; it does not touch `PlaybackController`. The swipe action (full-swipe) is attached to every scan row including the playing one (the ⋯ menu is hidden for it, swipe is not). The controller keeps `current` and the loaded song; `entry` becomes nil so the title falls back to the route title, and prev/next are disabled because `entryID` no longer resolves.

### Location
- `Sources/App/Player/LibraryScreen.swift:83-89` (swipe delete on all scans)
- `Sources/App/Player/LibraryScreen.swift:295-303` (delete)
- `Sources/App/Player/PlaybackController.swift:61-67,107-108` (entry/next/prev derive from store)
Root cause (1-2 lines): No coupling between playlist deletion and playback state.

### Repro
1. Play a scan; in Library swipe-delete the playing row.
2. Observe mini-player/playback continues; Next disabled.

Repro rate: always (code); device to confirm UI
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P3 — edge case with workaround.

### Suggested fix
In `LibraryScreen.delete`, if `controller.entryID == e.id` call `controller.stop()` and clear `current`; or hide Delete on the playing row. Combine with a confirm/undo for full-swipe delete.
