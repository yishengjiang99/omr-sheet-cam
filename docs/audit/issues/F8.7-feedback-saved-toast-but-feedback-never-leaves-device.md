**Static verdict from audit:** GAP (confirmed by code trace; product decision)
**Build / env:** traced at HEAD `736d0f6` (main) · iOS 17+ · static code trace, not yet reproduced on device/Simulator · StoreKit env: Xcode config (needs attach, see P11.3) / Sandbox · Apple ID type: sandbox tester

### Expected
Either feedback is actually delivered to the developer (with consent), or the UI says it is stored on this device only.

### Actual
The section "Was the reading accurate?" shows to all users with a "Save feedback" button and toast "Feedback saved". `save()` only records a `feedback` event in `DiagnosticsLog` (local `events.jsonl`); the only export is the developer-mode "Copy as prompt". Nothing is uploaded (consistent with the privacy page, but misleading to users).

### Location
- `Sources/App/Diagnostics/OMRCompareView.swift:227-258` (section, Save feedback button)
- `Sources/App/Diagnostics/OMRCompareView.swift:260-274` (save -> DiagnosticsLog only; toast at :269)
Root cause (1-2 lines): Feedback UI built for the developer workflow but visible to all users.

### Repro
1. Scan sample, open Result, set Overall verdict, tap Save feedback -> "Feedback saved".
2. Check network: no request; entry exists only in events.jsonl.

Repro rate: always
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P3 — misleading copy, no data impact.

### Suggested fix
Hide the feedback section unless developer mode is on, or relabel ("Save note on this device") and add an explicit opt-in "Send to developer" that uses the telemetry endpoint and is disclosed in the privacy policy.

- [ ] Manual: Non-developer user either does not see Save feedback or sees on-device wording; if Send exists, a POST is observed after consent.
- [ ] Automated: Unit test on section visibility (`showsDeveloperTools`/feature flag).
