### Expected
Every `purchase_start` has a terminal event (success/fail/cancel/pending); restore and paywall dismissal are measurable.

### Actual
`.userCancelled` and `@unknown default` return with no event; `.pending` is tracked as `purchase_fail{reason:pending}`; `restore()` and paywall Close emit nothing; no `pro_expired`/`pro_refunded`. Every thrown error is `reason:"error"` regardless of type, and `StoreKitError.userCancelled` thrown by `product.purchase()` would also count as `error`. Note: new event names must be added to the privacy policy event list and PrivacyInfo.xcprivacy text.

### Location
- `Sources/App/Services/StoreKitManager.swift:62-91` (events at :66,:75,:81,:88; none for cancel/unknown)
- `Sources/App/Services/StoreKitManager.swift:93-103` (no restore events)
- `Sources/App/Features/Paywall/PaywallView.swift:57-59` (Close: no event)
Root cause (1-2 lines): Events added only for the happy/fail paths.

### Repro
1. Subscribe, cancel in the Apple sheet; inspect telemetry requests: `purchase_start` with no follow-up.

Repro rate: always
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P3 — analytics gap only.

### Suggested fix
Add `purchase_cancel`, `purchase_pending` (instead of fail), `restore_start/success/fail/none`, `paywall_dismiss`; map `error` reason to a coarse error class (`network`, `storekit`, `verification`); update privacy page.
