### Expected
The review instructions are literally executable on a fresh install: Library home -> Try sample picture -> back -> repeat x6 -> paywall.

### Actual
`docs/asc/metadata/review_information/notes.txt` tells the reviewer to tap "Try sample picture" on the Library home screen, go back and repeat. The Library button is rendered only while `scans.isEmpty` (`LibraryScreen.swift:69-79`); the first successful sample scan auto-saves to the Library, so the button is gone on the next visit. The always-visible sample button exists only on the Camera screen (`CameraScreen.swift:48,153-164`); the notes' parenthetical "(or scan / import any sheet-music photo)" is the only hint. Reviewer can still reach the paywall via Camera or Photos, but may conclude the paywall is unreachable (Guideline 2.1).

### Location
- `docs/asc/metadata/review_information/notes.txt` (paragraph "How to reach the paywall")
- `Sources/App/Player/LibraryScreen.swift:69-79` (Try sample only when scans.isEmpty)
- `Sources/App/Capture/CameraScreen.swift:48,153-164` (always-visible sample button)
- `Sources/App/Capture/ResultScreen.swift:265-270` (auto-save to Library)
Root cause (1-2 lines): Review notes written against the empty-library UI; button is conditional.

### Repro
1. Fresh install; Library home: tap Try sample picture; wait for Result; Retake/back.
2. Library now lists the scan; "Try sample picture" is absent. Repeat instruction impossible from Library home.

Repro rate: always
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P2 — App Review friction/possible rejection, but a workaround path exists and is hinted.

### Suggested fix
Either (preferred) update notes.txt to say: "Library -> Camera icon -> Try sample picture (bottom of camera screen) x6, or Photos import any image"; or keep a persistent Try-sample control in Library (e.g. toolbar/menu). Re-submit notes via ASC.
