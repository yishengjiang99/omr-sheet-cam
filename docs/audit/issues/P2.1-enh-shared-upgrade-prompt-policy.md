### Summary
Today there is exactly one upgrade trigger: the quota wall. Every proposed new surface (post-scan card, remaining-scans nudge, Library/Settings row, app-return reminder, locked feature) needs the same cap, suppression and telemetry rules. Build that once.

### What the code does today
- Sole presenter: `ScanQuota.checkAndConsume()` sets `showPaywall = true` only when `used >= 5` (`Sources/App/Services/ScanQuota.swift:30-35`), emitting `free_quota_hit` + `paywall_trigger{reason:"quota"}` (:31-32).
- Presentation: `.sheet(isPresented: $quota.showPaywall) { PaywallView()... }` (`Sources/App/RootFlowView.swift:50-52`); Close at `Sources/App/Features/Paywall/PaywallView.swift:57-59`; `paywall_view` at :55; no `paywall_dismiss` event.
- No persisted prompt history exists (UserDefaults keys today: `omr.freeScansUsed`, `omr.freeScansDate`, `omr.isPro`, `omr.proTransactionId`).

### Proposed hook points (file:line at HEAD)
- `Sources/App/Services/ScanQuota.swift:6-13,30-35` - add `enum PaywallReason { quota, postScan, nudge, settings, library, appReturn, feature(String) }`, `@Published var paywallReason`, and `func requestPaywall(_ reason:) -> Bool` that applies the cap/suppression; keep the quota path calling it with `.quota` and bypassing the cap.
- `Sources/App/Services/ScanQuota.swift:11` + `Sources/App/RootFlowView.swift:15` - resolve the two-StoreKitManager duplication (issue [P1.12]) so suppression reads one source of truth.
- `Sources/App/Features/Paywall/PaywallView.swift:55,57-59` - pass the reason into `paywall_view{reason}` and emit `paywall_dismiss{reason}` (see [P10.2]).
- New small type `UpgradePromptPolicy` (UserDefaults keys `omr.upsell.lastShownAt`, `omr.upsell.shown7d`, `omr.upsell.sessionShown`, `omr.upsell.firstLaunchAt`) with injectable clock/defaults for tests.

### App Review guardrails (must all hold)
- Never blocks core use: scanning within quota, playback, Library, share and Settings stay fully usable; the prompt is dismissible and never re-appears in the same session after dismissal.
- Easy dismiss: visible Close/"Not now" control with no delay or countdown, swipe-down works, no dark patterns (no pre-checked purchase, no fake urgency/scarcity, no guilt copy).
- Frequency cap: shared policy (see the [P2.1] policy issue) - max 1 unsolicited prompt per calendar day and 3 per 7 days, never in the first session, never within 60 s of a previous prompt; the quota-hit paywall is user-initiated by the scan attempt and is exempt.
- Respect Pro/restored state: no prompt when `omr.isPro` is true (after the P7.4 fix, the live entitlement) or while a purchase/restore/pending approval is in progress.
- Accurate disclosure (Guideline 3.1.2): any screen that shows a price also shows billing period, renewal text, Terms and Privacy links and a Restore control, exactly as the existing PaywallView does.
- Telemetry (if added) uses the existing anonymous funnel only and the new event names are added to the privacy page and PrivacyInfo text before release.

### Acceptance checks
