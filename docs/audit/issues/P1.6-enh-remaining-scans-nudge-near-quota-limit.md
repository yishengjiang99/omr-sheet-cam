### Summary
The first time the user learns about the limit is the 6th scan (paywall). Show a quiet counter that becomes a tappable nudge when 2 or fewer scans remain, so the wall is not a surprise and users can upgrade on their own terms.

### What the code does today
- `ScanQuota.scansRemaining` exists (`Sources/App/Services/ScanQuota.swift:40-45`) but no view reads it (rg shows only its definition); it is also a computed var, not `@Published`, so SwiftUI would not refresh.
- Counter writes happen at `ScanQuota.swift:25-29,36` straight to UserDefaults.
- Library scan CTAs: `Sources/App/Player/LibraryScreen.swift:158-190` (`scanActions`) inside the home Section (:55-67). Camera top bar: `Sources/App/Capture/CameraScreen.swift:116` (`topBar`).

### Proposed hook points (file:line at HEAD)
- `Sources/App/Services/ScanQuota.swift:36,40-45` - add `@Published private(set) var remaining: Int` updated in `checkAndConsume()` after the increment and in `init`/foreground (day rollover); expose `isPro` through the shared manager.
- `Sources/App/Player/LibraryScreen.swift:158-190` - under `scanActions` add a footnote `Text("\(remaining) free scans left today")` for free users (always visible, quiet); when `remaining <= 2` make it a Button that calls `requestPaywall(.nudge)`.
- `Sources/App/Capture/CameraScreen.swift:116-` - same small capsule in `topBar`; do not overlap the shutter/hint.
- Hide for Pro and while the quota state is unknown (before first refresh).

### App Review guardrails (must all hold)
- Never blocks core use: scanning within quota, playback, Library, share and Settings stay fully usable; the prompt is dismissible and never re-appears in the same session after dismissal.
- Easy dismiss: visible Close/"Not now" control with no delay or countdown, swipe-down works, no dark patterns (no pre-checked purchase, no fake urgency/scarcity, no guilt copy).
- Frequency cap: shared policy (see the [P2.1] policy issue) - max 1 unsolicited prompt per calendar day and 3 per 7 days, never in the first session, never within 60 s of a previous prompt; the quota-hit paywall is user-initiated by the scan attempt and is exempt.
- Respect Pro/restored state: no prompt when `omr.isPro` is true (after the P7.4 fix, the live entitlement) or while a purchase/restore/pending approval is in progress.
- Accurate disclosure (Guideline 3.1.2): any screen that shows a price also shows billing period, renewal text, Terms and Privacy links and a Restore control, exactly as the existing PaywallView does.
- Telemetry (if added) uses the existing anonymous funnel only and the new event names are added to the privacy page and PrivacyInfo text before release.
