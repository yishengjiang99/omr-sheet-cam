**Type:** Product enhancement (not a defect). Traced at HEAD `736d0f6`.

### Summary
A once-in-a-while, dismissible banner (not a sheet) on the Library when a free user returns after a few days. It must never interrupt scanning, playback, or appear mid-flow.

### What the code does today
- No scene-phase handling at the root: `RootFlowView` has no `scenePhase` observer (`Sources/App/RootFlowView.swift:19-55`); only `CameraScreen` observes it (`Sources/App/Capture/CameraScreen.swift:23,55-58`).
- Cold-start work lives in `OMRSheetCamApp.init` (`Sources/App/OMRSheetCamApp.swift:7-14`); `Analytics.bootstrap()` already emits `session_start`/`app_open`.
- Entitlement is refreshed only in `StoreKitManager.init` (`StoreKitManager.swift:23-28`), so the same hook is the natural place to fix bug [P7.4].

### Proposed hook points (file:line at HEAD)
- `Sources/App/RootFlowView.swift` after `.environmentObject(storeKit)` (:53) - add `@Environment(\.scenePhase)` and `.onChange(of: scenePhase) { if $1 == .active { await storeKit.refreshEntitlements(); quota.maybeShowReturnBanner() } }` (refresh first so lapsed/Pro state is correct before deciding).
- `Sources/App/Player/LibraryScreen.swift:55-67` - render the banner inside the home Section only when `path.isEmpty` (Library visible), no playback active (`controller.current == nil` or paused), >= 3 days since last visit, policy allows (`.appReturn`).
- Copy example: "Welcome back - Pro gives unlimited scans" with "See Pro" and a clear "Not now" (no countdown). Tapping See Pro uses `requestPaywall(.appReturn)`.

### App Review guardrails (must all hold)
- Never blocks core use: scanning within quota, playback, Library, share and Settings stay fully usable; the prompt is dismissible and never re-appears in the same session after dismissal.
- Easy dismiss: visible Close/"Not now" control with no delay or countdown, swipe-down works, no dark patterns (no pre-checked purchase, no fake urgency/scarcity, no guilt copy).
- Frequency cap: shared policy (see the [P2.1] policy issue) - max 1 unsolicited prompt per calendar day and 3 per 7 days, never in the first session, never within 60 s of a previous prompt; the quota-hit paywall is user-initiated by the scan attempt and is exempt.
- Respect Pro/restored state: no prompt when `omr.isPro` is true (after the P7.4 fix, the live entitlement) or while a purchase/restore/pending approval is in progress.
- Accurate disclosure (Guideline 3.1.2): any screen that shows a price also shows billing period, renewal text, Terms and Privacy links and a Restore control, exactly as the existing PaywallView does.
- Telemetry (if added) uses the existing anonymous funnel only and the new event names are added to the privacy page and PrivacyInfo text before release.

### Acceptance checks
- [ ] Manual: free user returning after 3+ days sees at most one banner on Library; "Not now" hides it and it does not return for 7 days; never shown during scan/Reading/Player; Pro/lapsed state corrected before showing.
- [ ] Automated: `UpgradePromptPolicyTests` - appReturn only on `.active` after >=3 days, suppressed for Pro, suppressed within cap; XCUITest background/foreground with injected clock.
- [ ] Regression: P7.1/P7.4 (refresh on foreground), F1.1 launch, F3.10 camera restart on active.
