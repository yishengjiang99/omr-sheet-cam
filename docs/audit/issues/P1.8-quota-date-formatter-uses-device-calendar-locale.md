### Expected
The stored day key is calendar/locale independent (`yyyy-MM-dd` Gregorian, POSIX locale), as `CaptureStore.timestamp` already does.

### Actual
`ScanQuota.today` builds a `DateFormatter` with only `dateFormat = "yyyy-MM-dd"`; it inherits the user's current locale and calendar. Under a non-Gregorian calendar (Buddhist, Japanese, Hijri) the year differs, and switching region/calendar between scans changes the string and resets the counter early. Also a new `DateFormatter` is allocated on every access (`today` is read twice per check).

### Location
- `Sources/App/Services/ScanQuota.swift:15-19`
- `Sources/App/Capture/CaptureStore.swift:24-29` (correct pattern with en_US_POSIX)
Root cause (1-2 lines): Formatter lacks locale/calendar pinning.

### Repro
1. Use 5 scans. Settings > General > Language & Region > Calendar: Buddhist.
2. Next scan: stored date != today string -> counter reset -> 5 more scans.

Repro rate: needs device only (calendar switch)
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P3 — edge-case quota bypass; the quota is already trivially bypassable via clock (P1.9, product decision).

### Suggested fix
Set `f.locale = Locale(identifier: "en_US_POSIX")`, `f.calendar = Calendar(identifier: .gregorian)`; cache formatter; inject a clock for tests.
