**Step ID:** F2.7 (also F13.5, F6.8)
**Flow:** F2 Library home (browse / search / rename / delete)
**Static verdict from audit:** GAP (confirmed by code trace)
**Build / env:** traced at HEAD `736d0f6` (main) · iOS 17+ · static code trace, not yet reproduced on device/Simulator · StoreKit env: Xcode config (needs attach, see P11.3) / Sandbox · Apple ID type: sandbox tester

### Expected
Deleting a scan removes the index entry, `.mid`, `.layout.json` AND the capture JPEG `Documents/captures/<captureName>`. The live privacy policy states: "Scans, MIDI files, and titles the app creates are saved only on your device. Deleting a scan or the app removes them."

### Actual
`PlaylistStore.delete` removes only `<name>.mid` and `<name>.layout.json`. `PlaylistEntry.captureName` records the JPEG but it is never deleted, so every scanned photo accumulates in the app's Documents folder (visible in Files if file sharing is on, and included in iCloud backups) with no in-app way to remove it. Existing test only asserts the `.mid` removal.

### Location
- `Sources/App/Player/PlaylistStore.swift:158-168` (delete: no capture removal)
- `Sources/App/Player/PlaylistStore.swift:19,138-141` (captureName stored)
- `Sources/App/Capture/CaptureStore.swift:18-21` (Documents/captures)
- `Sources/App/Player/LibraryScreen.swift:295-303` (delete UI)
- `docs/asc/web/privacy.html:14 and https://grepawk.com/music-reader/privacy.html` ("Deleting a scan ... removes them")
- `Tests/PlaylistStoreTests.swift:82-103` (does not cover capture file)
Root cause (1-2 lines): Delete was written for playlist files only; capture storage lives in a different directory managed by `CaptureStore`.

### Repro
1. Scan sample picture -> note `Documents/captures/<stamp>.jpg` exists (Developer log shows `saved captures/...`).
2. Library > swipe Delete the scan.
3. Check container Documents/captures: JPEG still present.

Repro rate: always
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P1 — privacy statement violated per rubric (P0 definition); downgraded to P1 here because data stays in the app sandbox on the user's own device - raise to P0 if you want to follow the rubric literally.

### Suggested fix
In `delete(_:)` also remove `CaptureStore.defaultDirectory()/removed.captureName` (try? and log). Add a one-time cleanup of orphan captures not referenced by any entry (also covers F6.8 cancelled scans). Consider `isExcludedFromBackup` for captures.
