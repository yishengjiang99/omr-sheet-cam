**Type:** Product enhancement (not a defect). Traced at HEAD `736d0f6`.

### Summary
Give free users a self-serve way to see Pro and upgrade (without hitting the wall), and give Pro users visible confirmation, plan info and Manage subscription / Restore.

### What the code does today
- Settings sections are only Playback / About / Developer (`Sources/App/Settings/SettingsView.swift:57-67`; `sections(developerEnabled:)`, `aboutRows`), no Pro row.
- Library home Section (`Sources/App/Player/LibraryScreen.swift:55-67`) has HowItWorks art, Camera/Photos CTAs and import error only.
- Paywall only opens from the quota gate (`ScanQuota.swift:33`); there is no `manageSubscriptionsSheet`.

### Proposed hook points (file:line at HEAD)
- `Sources/App/Settings/SettingsView.swift:57-67` - add `.pro` to `Self.sections` (tested static function) rendering a `proSection`: free -> "Music Reader Pro" row (opens paywall via `requestPaywall(.settings)`; exempt from the cap because user-initiated) + "Restore purchases" (fixes bug [P6.1]); Pro -> "Music Reader Pro - active" + renewal/expiry date (from `Transaction.currentEntitlements`) + `.manageSubscriptionsSheet`.
- `Sources/App/Player/LibraryScreen.swift:55-67` - optional small "Go Pro" capsule/toolbar item for free users only (hidden for Pro); no animation, no badge counters.
- `Sources/App/Features/Paywall/PaywallView.swift:83-84` - on success show confirmation ("You're Pro - unlimited scans") instead of silent dismiss.
- Needs the single shared `StoreKitManager` (issue [P1.12]) with a published `isPro`.

### App Review guardrails (must all hold)
- Never blocks core use: scanning within quota, playback, Library, share and Settings stay fully usable; the prompt is dismissible and never re-appears in the same session after dismissal.
- Easy dismiss: visible Close/"Not now" control with no delay or countdown, swipe-down works, no dark patterns (no pre-checked purchase, no fake urgency/scarcity, no guilt copy).
- Frequency cap: shared policy (see the [P2.1] policy issue) - max 1 unsolicited prompt per calendar day and 3 per 7 days, never in the first session, never within 60 s of a previous prompt; the quota-hit paywall is user-initiated by the scan attempt and is exempt.
- Respect Pro/restored state: no prompt when `omr.isPro` is true (after the P7.4 fix, the live entitlement) or while a purchase/restore/pending approval is in progress.
- Accurate disclosure (Guideline 3.1.2): any screen that shows a price also shows billing period, renewal text, Terms and Privacy links and a Restore control, exactly as the existing PaywallView does.
- Telemetry (if added) uses the existing anonymous funnel only and the new event names are added to the privacy page and PrivacyInfo text before release.

### Acceptance checks
- [ ] Manual: Settings shows the Pro row for free and Pro users; Restore works from Settings with zero scans used; Pro shows plan + Manage subscription; Library capsule absent for Pro.
