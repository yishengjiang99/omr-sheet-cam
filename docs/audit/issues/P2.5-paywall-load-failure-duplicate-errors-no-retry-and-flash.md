**Step ID:** P2.5 (also P2.7)
**Flow:** P2 Paywall presentation & StoreKit product load
**Static verdict from audit:** GAP (confirmed by code trace)
**Build / env:** traced at HEAD `736d0f6` (main) · iOS 17+ · static code trace, not yet reproduced on device/Simulator · StoreKit env: Xcode config (needs attach, see P11.3) / Sandbox · Apple ID type: sandbox tester

### Expected
Offline/empty product list -> one clear message and a Retry button that reloads without dismissing; while loading show a spinner and never show the error before the request starts.

### Actual
(a) `loadProducts()` catch sets `purchaseError = "Could not load products: ..."` (red box) while `products` stays empty, so the grey "Could not load products. Check your connection and try again." line also renders: two messages, and there is no retry control (reload happens only on re-presenting). (b) `isLoading` is false until `.task` runs, so on the first render `products.isEmpty && !isLoading` is true and the error text flashes; there is no ProgressView at all while loading (only inside Subscribe buttons during a purchase).

### Location
- `Sources/App/Services/StoreKitManager.swift:46-60` (catch sets purchaseError; isLoading only inside the call)
- `Sources/App/Features/Paywall/PaywallView.swift:27-31` (empty-state message condition)
- `Sources/App/Features/Paywall/PaywallView.swift:35-41` (second message)
- `Sources/App/Features/Paywall/PaywallView.swift:61` (.task load; no retry button anywhere)
Root cause (1-2 lines): Load state is inferred from `products.isEmpty`/`isLoading` instead of an explicit `.loading/.loaded/.failed` state.

### Repro
1. Airplane mode, or run without a StoreKit config attached (see P11.3).
2. Hit the paywall. First frame: grey "Could not load products..." flashes; after the failed request a red duplicate appears.
3. Look for Retry: none.

Repro rate: always
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P2 — misleading on every first paywall presentation; the only recovery is dismissing and re-triggering.

### Suggested fix
Add `enum LoadState { idle, loading, loaded, failed(String) }`; show ProgressView for `.loading/.idle`, one message + "Try again" button (calls `loadProducts()`) for `.failed`/empty; do not reuse `purchaseError` for load errors.
