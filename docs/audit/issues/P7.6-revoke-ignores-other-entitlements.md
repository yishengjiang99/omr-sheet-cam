title: [P7.6] Refunding one subscription locks Pro even when another entitlement is still valid

**Step ID:** P7.6 (also P7.7, P3.8)
**Flow:** P7 Entitlement checks, renewal, expiry, refund, offline
**Static verdict from audit:** GAP (confirmed by code trace)
**Build / env:** traced at HEAD `736d0f6` (main) · iOS 17+ · static code trace, not yet reproduced on device/Simulator · StoreKit env: Xcode config (needs attach, see P11.3) / Sandbox · Apple ID type: sandbox tester

### Expected
Pro is removed only if no other valid entitlement remains (e.g. buy yearly, then monthly, refund monthly -> still Pro). A delivered transaction that is expired/superseded must not grant Pro.

### Actual
The `Transaction.updates` listener calls `revokePro()` unconditionally for any revoked transaction of either product, writing `omr.isPro=false` without re-running `refreshEntitlements()`. The user stays locked out until next launch. Conversely, the grant branch only checks `revocationDate == nil`; it does not check `expirationDate` or `isUpgraded`, so a replayed old/expired/superseded transaction sets `omr.isPro=true` until next launch.

### Location
- `Sources/App/Services/StoreKitManager.swift:110-116` (grant if revocationDate == nil, else revokePro unconditionally)
- `Sources/App/Services/StoreKitManager.swift:148-151` (revokePro)
- `Sources/App/Services/StoreKitManager.swift:124-141` (correct recompute exists but is not called from the listener)
Root cause (1-2 lines): Listener mutates the flag per-transaction instead of recomputing from `Transaction.currentEntitlements`.

### Repro
1. StoreKit config: buy Yearly, then Monthly (same group; or use two entitlements in test session).
2. Transaction Manager: refund/revoke the Monthly transaction.
3. Next scan #6/day: paywall shown although Yearly is still valid. (Reverse: replay an expired transaction -> flag true.)

Repro rate: always (static)
Evidence: static trace at HEAD with file:line above (no screenshot/recording yet)

### Severity
P2 — edge case, paying user wrongly locked until relaunch; self-heals on relaunch.

### Suggested fix
In `listenForTransactions`, after handling any update call `await refreshEntitlements()` (single source of truth) and drop the per-transaction grant/revoke; still `finish()` verified transactions.
